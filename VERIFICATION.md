## Known issues / recommended before publishing

1. **`pnpm check-types` and `pnpm lint` fail in `screenshot-studio`** — 122 errors, all `react-konva` JSX components (`TS2604`/`TS2786`) plus implicit `any` params. Cause: your bump of `@types/react` from `19.2.14` → `19.3.0`. I proved this by temporarily installing `@types/react@19.2.14`: typecheck then passed cleanly. I restored your `19.3.0` choice. **This does not affect the build, tests, published tarball, or runtime** — `pnpm build` and `pnpm test` are green. If you want the quality gates green, pin `@types/react` back to `19.2.14` in that one package.
2. **`pnpm publish --dry-run` fails in `postbuild`** — `attw` calls `npm pack`, but dry-run mode sets `npm_config_dry_run=true`, so no tarball is written and `attw` reports `ENOENT … .tgz`. A real `pnpm publish` is unaffected. Use `pnpm build` + `pnpm check-exports` as your preflight instead (both pass).
3. **`release` scripts are broken** — they call `changeset publish:<package>`, but there is no `.changeset/` directory or such a changesets command. `pnpm release` will fail; publishing with `pnpm --filter <pkg> publish` works and is what the README instructs.
4. **`image-size@2.0.2`** (social-inspect dependency) has two high-severity DoS advisories (GHSA-5p2g-fcmc-qvqq, GHSA-w3rx-r6r6-pgpr). `2.1.0` is available and patches them. Not a blocker for a local inspector, but a one-line bump if you want a clean `npm audit`.
5. The `screenshot-studio` MCP endpoint remains experimental/unauthenticated, as noted in the main README.
